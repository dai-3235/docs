# Teach the design with a fictional ad-reporting domain

The series explains semantic-layer design using an invented ad-reporting world, so every post stands alone as teaching material.

- The system is called "a semantic query gateway", never by a product name, and posts use a neutral voice that makes no claims about who built what.
- Technology is described by category (a JVM service, several SQL engines over JDBC, a columnar analytics store, a row store, a lakehouse), not by product.
- Posts cover design ideas, algorithms and trade-offs only. No traffic, latency or size numbers, no team or timeline details, no customers, incidents or roadmap.
- The ad domain uses generic industry terms with an invented schema, invented table and column names, and an invented grain hierarchy.
- Comparisons with other systems use only claims that can be checked against that system's own documentation or engineering posts, and each one links its source.
- Publication needs the owner's explicit sign-off before a post is merged.
